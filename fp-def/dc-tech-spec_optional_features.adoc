[role="lead"]
NetApp admite varios componentes opcionales para mejorar aún más las arquitecturas de centros de datos de FlexPod. Los componentes opcionales se describen en las subsecciones siguientes.


NOTE: El arranque SAN es opcional, pero se recomienda encarecidamente, ya que permite trasladar el perfil del servidor durante las actualizaciones o reemplazos de hardware.



[[iscsi-boot-option]]
== Opción de arranque iSCSI

Los requisitos mínimos para la opción de arranque iSCSI incluyen:

* Una función o licencia de iSCSI activada en la controladora de almacenamiento de NetApp
* Un adaptador Ethernet de dos puertos 10 Gbps en cada nodo del par de alta disponibilidad de la controladora de almacenamiento de NetApp
* Un adaptador en el servidor Cisco UCS que sea capaz de arrancar iSCSI

[[fc-boot-with-cisco-mds]]
== Arranque de FC con Cisco MDS

Para ofrecer una mayor escalabilidad mediante el uso de una red SAN dedicada, FlexPod es compatible con FC a través de los switches Cisco MDS. La opción de arranque SAN FC a través de Cisco MDS tiene los siguientes requisitos de modelo de licencia y hardware:

* Un mínimo de dos puertos FC por controladora de almacenamiento de NetApp; un puerto por cada estructura DE SAN
* Una licencia FC en cada controlador de almacenamiento de NetApp.
* Un adaptador en el servidor Cisco UCS que es capaz de arrancar mediante FC.

image:dc-tech-spec_image16.png["FlexPod Datacenter para conectividad SAN basada en FC"]

[[end-to-end-fc-nvme]]
== FC-NVMe integral

Una solución FC-NVMe de extremo a extremo amplía de forma fluida la infraestructura SAN existente del cliente para aplicaciones en tiempo real, al mismo tiempo que ofrece más IOPS y mayor rendimiento con menor latencia. Se puede usar una red SAN FC de 32G ya existente para transportar simultáneamente cargas de trabajo NVMe y SCSI.

Para obtener más información sobre esta configuración, consulta link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter con Cisco UCS M7 IMM, VMware vSphere 8.0 y NetApp ONTAP 9.12 Guía de diseño"^].



[[cisco-ucs-x-series-direct-and-direct-attached-aff-asa-fas-for-fc-and-ip-based-san]]
== Cisco UCS X-Series Direct y AFF, ASA y FAS conectados directamente para SAN basadas en FC e IP

Los controladores de almacenamiento NetApp pueden conectarse directamente a las interconexiones de estructura Cisco UCS sin ningún switch SAN aguas arriba. FlexPod admite tanto el arranque por FC como por iSCSI con UCS X-Series Direct.

Los requisitos de licencia y hardware son los siguientes:

* Se requiere una licencia de protocolo en la controladora de almacenamiento de NetApp.
* Se requiere un adaptador Cisco UCS (iniciador) en el servidor. Para consultar la lista de adaptadores Cisco UCS compatibles, consulta NetApp https://imt.netapp.com["IMT"^].
* Se requiere un adaptador de destino en la controladora de almacenamiento de NetApp.

image:dc-tech-spec_image13.png["Topología ASA de conexión directa y conexión directa de UCS X-Series para SAN basada en IP"]

*Notas:*

* Cisco UCS se configura en el modo de conmutación Ethernet.
* Los puertos iSCSI del destino a las interconexiones de estructura se configuran como puertos de almacenamiento Ethernet para datos iSCSI.


La siguiente figura muestra una topología de UCS X-Series Direct y ASA de conexión directa para redes SAN basadas en IP y en FC.

*Notas:*

[[metrocluster]]
== MetroCluster

FlexPod MetroCluster IP con solución de estructura VXLAN multisede consiste en dos FlexPods, ubicados en dos sitios separados por cierta distancia, pero conectados y emparejados para ofrecer una solución de centro de datos altamente disponible, muy flexible y muy fiable que puede proporcionar continuidad del negocio incluso ante un fallo del sitio. La distancia máxima admitida entre los sitios es de aproximadamente 435 millas (700 km).

En la solución IP FlexPod MetroCluster, la solución Cisco VXLAN Multi-Site permite interconectar y gestionar de forma centralizada las VXLAN fabrics implementadas en centros de datos independientes y geográficamente dispersos. NetApp MetroCluster IP ofrece una solución de replicación síncrona entre dos clústeres de almacenamiento NetApp, proporcionando alta disponibilidad del almacenamiento y recuperación ante desastres en un campus o en un área metropolitana. La solución te permite diseñar una nube privada basada en VMware vSphere sobre una infraestructura integrada distribuida y ofrecer una solución unificada que permite que varios sitios funcionen prácticamente igual que un solo sitio, mientras protege los servicios de datos frente a diferentes escenarios de punto único de fallo, incluido el fallo total del sitio.

[[snapmirror-active-sync-solution-for-flexpod-metrocluster-ip-solution]]
=== Solución SnapMirror active sync para la solución IP de FlexPod MetroCluster

Usando la tecnología Snapshot de NetApp en el software NetApp ONTAP, los servicios de datos SAN de misión crítica pueden restaurarse rápidamente con datos de copias de seguridad basadas en Snapshot.

* Los dos clústeres ONTAP implementados en dos sitios diferentes están emparejados y configurados con SnapMirror active sync para la replicación síncrona de datos y la recuperación ante desastres.
* El mediador ONTAP se implementa en un tercer dominio de fallo, como se muestra en la figura a continuación. Junto con los clústeres, el mediador ONTAP completa el quórum para la solución SnapMirror active sync.
* El mediador de ONTAP recibe información sobre el estado de los clústeres y nodos ONTAP conectados en paridad y coordina su funcionamiento para determinar su estado. Los datos sobre el estado ayudan a los clústeres a distinguir entre distintos tipos de fallos y a decidir si deben realizar una conmutación automática al respaldo.
